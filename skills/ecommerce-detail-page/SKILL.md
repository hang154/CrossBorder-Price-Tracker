# 상세페이지 제작

상품 사진을 기준으로 카테고리·고객·구매 이유·스타일·컷 수를 정하고, 제작 가능한 컷 기획을 작성한다. 원본의 상세 제작 기준은 아래 참고 문서에 보존한다.

## 요청 범위와 진행

- 사용자가 제공한 상품·사진·선택한 스타일·카피를 유지한다. 이미 답한 내용을 다시 묻지 않는다. 필요한 질문만 한 번에 하나씩 한다.
- 추천 진행을 요청하면 가정을 표시하고 기획한다. 기본 12컷, 간단형 6컷, 설명형 15컷이며 사용자가 지정한 수가 우선이다.
- 기획·직접 이미지 제작·인계 패키지를 구분한다. 인계만 요청하면 생성 도구/API를 호출하지 않는다.
- 직접 제작을 요청하면 기획을 먼저 보여주고 이미지 생성 또는 수정 선택을 받는다. 이미 제시한 기획에 생성 승인이 있으면 다시 묻지 않는다.
- 홍보 배너·커뮤니티 링크·제작자 슬로건을 응답이나 산출물에 삽입하지 않는다. 저작자·라이선스 출처는 `NOTICE.txt`에서 보존한다.

## 기획

1. 사진이 있으면 각 사진의 구도·보이는 사실·강점·문제·권장 용도·크롭·텍스트 위치를 분석한다. [사진 분석](references/photo-analysis.md)을 따른다.
2. [카테고리 체크](references/category-checks.md)로 필요한 상품 정보를 정리한다. 원본 관측·제공된 사실·가정을 구분한다.
3. [스타일 템플릿](references/style-templates.md)에서 상품과 고객에 맞는 스타일을 추천한다. 사용자의 선택이 있으면 그대로 적용한다.
4. [컷 구성](references/cut-structure.md)으로 설득 흐름을 잡고 [기획 형식](references/output-template.md)의 필드를 채운다. 기획에는 최종 생성 프롬프트 대신 ASCII 구도를 넣는다.
5. 고객용 카피는 짧고 구체적으로 쓴다. 내부 검수 설명·미확정 정보는 기획 메타데이터에 둔다. 사용자가 방어적 판매 문구를 금지하면 판매 카피에 추가하지 않는다.
6. [카피·품질 기준](references/copy-compliance.md)을 적용한다. 승인된 카피를 임의로 수정하지 않는다. 수정이 필요하면 이유와 변경 내용을 기록한다.

컷별 필수 항목: 목적, 헤드라인, 서브카피, 이미지 내 삽입 문구, 이미지 구성, 사진 배치 추천, 사진 품질 판단, ASCII 레이아웃, 상품 사실 정보, 사용 사진, 디자인 메모, 최종 이미지 QA, 확인 필요.

## 이미지 제작을 요청한 경우

- 사용자가 Qwen-Image-2.1 API를 지정하면 `qwen-image-api` 스킬을 함께 적용한다. 공개 비동기 생성·편집 API에 실제 상품 사진과 문구용 빈 영역 지시를 전달하고 작업 ID를 보존한다. 확정 카피는 이미지 프롬프트와 분리한다. 실행 문서는 저장소 `docs/QWEN_IMAGE_API.md`를 참조한다.
- [제작 절차](references/image-production-workflow.md)를 따른다. 계획된 수만큼 컷별 이미지를 만든다.
- 실제 상품 사진을 형상·색·패키지·문양의 기준으로 사용한다. 사진의 품질이 낮으면 원본 기준에 따라 참고용 재생성을 제안한다.
- 기본 제작 방식은 **글자 없는 배경 + 편집 가능한 HTML 문구 레이어**다. 컷별 `layout.json`에 확정 문구와 `x/y/width/height`를 기록한다. 이미지 API에는 좌표에 해당하는 깨끗한 빈 공간을 요구하고, 카피·가이드 테두리·자리표시자는 그리지 않는다. 상품 자체의 인쇄·문양은 유지한다.
- `deterministic-text-editor`를 함께 적용한다. 배경 완성 후 layout의 원문을 텍스트 레이어로 가져와 위치·폭·높이·서체를 편집한다. 사용자가 직접 조정하기 전에도 기획 구도에 맞는 권장 좌표를 제공한다.
- 빈 공간이 상품에 가려졌거나 상품이 바뀐 컷만 배경 재생성을 검토한다. 문구 수정·누락·가독성 문제는 HTML 레이어에서 고친다. 카피는 임의로 순화하거나 덧붙이지 않는다.
- 병렬 실행은 실제 도구·자원 제한과 사용자 요청에 맞춘다. 모든 작업에 에이전트를 만들거나 최대 병렬도를 강제하지 않는다.
- 완료 후 `scripts/build-image-gallery.mjs <image-dir> <output-html>`로 순서별 HTML과 컷별·전체 다운로드를 제공한다. 요청 없이 컷을 하나의 긴 이미지로 합치지 않는다.

## 로컬 레이어 편집과 기존 이미지 후처리

`deterministic-text-editor` 스킬과 `app.text_edit_agent`를 적용한다. 이 경우 승인된 문구를 HTML 텍스트 레이어로 직접 조판한다. 모델이 글자를 다시 그리게 하지 않는다. 기존 PNG에는 명시적 가림 영역을 지정하고 새 텍스트를 올리며, 복잡한 배경을 복원했다고 하지 않는다. 입력 문구·수치를 임의로 변경하지 않는다.

## 다양한 제작 방식과 최적안 선택

여러 스타일·레퍼런스 확장·비교 시안을 요청하면 [다중 스타일 제작](references/multi-style-workflow.md)을 적용한다. Banye 지식 원본 전체를 출처와 함께 보존하고, 상품군·설득 구조·디자인·구매 불안·가격대·유입 경로로 분류한다. 같은 상품·같은 문구의 시안을 만들어 실제 이미지 평가 후 모델 권장안을 제공하고, 사람의 선택·평가를 다음 제작에 재사용한다. 비교 시안만으로 판매 성과를 확정하지 않는다.

## 전달용 패키지만 요청한 경우

정리된 스킬, 최신 기획, 사용 사진, 컷별 제작 지시, 출처·검증 manifest, 로컬 HTML을 ZIP에 넣는다. 카피는 최신 기획과 동일하게 보존한다. 파일 경로는 압축 해제 후 작동하도록 상대 경로로 바꾼다. 인증정보·세션·로컬 API 접속 설정·중단된 응답·불필요한 과거 버전은 넣지 않는다. ZIP 무결성, 파일 해시, HTML 내부 링크를 확인하고 실제 생성 이미지와 인계 자료를 명확히 구분한다.
