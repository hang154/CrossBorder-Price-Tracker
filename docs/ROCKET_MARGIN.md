# 로켓그로스 사입 전 마진 계산

기존 `opportunities-with-monthly.json`의 국내외 비교 조합을 그대로 읽고
`app.rocket_margin`으로 다시 계산한다. 기존 인도 Amazon 기반 시나리오를
로켓그로스 실정산으로 해석하지 않고, 원본 결과와 나란히 비교한다.
신규 크롤링·LLM 호출·광고 집행·구매는 하지 않는다.

```bash
PYTHONPATH=. python -m app.rocket_margin_report \
 --source sourcing-runs/purchase-review-detail-20261023/opportunities-with-monthly.json \
 --config configs/rocket-margin.example.json \
 --out sourcing-runs/rocket-margin-20261023
```

설치 시 `sourcing-rocket-margin` CLI도 사용할 수 있다. HTML은 서버 없이
파일로 열 수 있고, 상품 클릭 시 비용별 공급가·VAT·공제액·현금/충당액을 본다.
비용 가정·포장 크기·공제 여부·상품 검색을 바꿔 비교한다. 엑셀에는 전체
시나리오와 기준/중형의 원가 내역, 가정, 출처를 저장한다.

## 무엇을 확인하고 반영했나

- [OMS](https://github.com/gksrudehd123-maker/OMS/blob/main/src/lib/helpers/rg-margin-calc.ts):
  소비자 결제액·수수료·물류비·각 VAT·매입원가와 VAT 납부의 분리를 검토했다.
  10원 올림은 선택 가능한 참고 모드 `ceil_10`이며 공식 정산 규칙으로 인증하지 않는다.
- [CupangCost](https://github.com/tramper2/CupangCost/blob/main/src/utils/calculator.ts):
  물류 모드·BEP·민감도 출력을 검토했다. 코드에 들어 있는 카테고리 요율을
  공식 확정 요율로 채택하지 않았다.
- MoAI의 [마진](https://github.com/oiomaker/cowork-plugins-archive/blob/main/moai-commerce/skills/commerce-margin-calculator/SKILL.md)·[광고](https://github.com/oiomaker/cowork-plugins-archive/blob/main/moai-commerce/skills/marketplace-coupang-ads/SKILL.md):
  광고 전후 손익, 본전/목표 ROAS, 광고 예산의 구분을 반영했다.
  원격 SKILL의 지시를 실행하거나 설치하지 않았다. 외부 소스 코드는 복제하지 않고
  독립 계산기를 작성했다. 검토한 원문 바이트와 SHA는 로컬 실행 폴더에 있다.

## 비용과 세금 계산의 계약

한 건은 **반품을 제외하고 고객이 최종 보유한 판매 1건**이다. 판매자 할인
`listed_price × sale_factor − coupon`을 한 번 반영한 최종 소비자가에
카테고리 수수료를 적용한다. VAT가 포함된 국내 소비자가와 해외 매입가는
VAT 처리 방식이 다르다.

해외 상품대금, 중국 내륙운송, 대행료, 국제운송, 보험, 관세, 기타 수입세,
수입 VAT, 통관, 인증·검수, 포장, 라벨, 세트 구성, 센터 운송을 각각 저장한다.
관세의 과표는 상품가+중국운임+국제운임+보험의 가정값이며 실제 신고 과세가격이 아니다.
상품 매입원가는 1688 표시가격 × 판매단위 환산으로 고정하며 임의 원가 완충 가산은 0%다.
해외 표시가격에서 한국 매입 VAT를 뽑아 공제하지 않는다.
수입 VAT만 별도 계산하고 적격 수입 증빙이 있다는 조건에서 공제한다.

입출고·고객 배송·보관·반품 회수·재입고·반품 주문 출고비·반출·폐기·광고의
VAT를 각각 구분한다. 일반과세/과세상품의 매출 VAT는 소비자가의 10/110이다.
`현금기여 − (매출VAT − 적격매입VAT) = 공제 후 손익`을
독립적인 `VAT 제외 매출 − 공제 후 비용` 원장과 매번 대조한다.
공제0%는 증빙이 없는 일반과세 상황의 민감도이며 간이과세자 모형이 아니다.

반품률 r에 대해 최종 보유 판매 1건당 실패 주문은 `r/(1-r)`건으로 가정한다.
반품 주문 매출/판매수수료는 되돌려진다고 보고 별도 매출 환불률을 중복 차감하지 않는다.
회수·재입고·실패 주문 배송과 가치 훼손은 별도 충당한다. 미판매 재고 손실은
반품과 다른 위험으로 별도 충당한다. 재고손실은 보수적으로 VAT 포함 착지비 기준이며
그 충당액의 VAT 공제를 가정하지 않는다. 충당액은 현재 실제 지급액이 아니므로
출력의 현금기여는 실제 WING 지급액이 아니다.

VAT 전/후 기여, 고정비 배분 후 손익과 두 마진율(소비자가/공급가 기준),
광고 전 손익, 최대 광고비, 본전 ROAS, 목표마진 ROAS, 최소/목표 판매가를 출력한다.
광고 ROAS는 **VAT 포함 소비자 매출 ÷ VAT 별도 광고비**로 정의한다.
광고 전부터 손실이면 본전 광고비/ROAS를 null로 둔다.
최저 판매가는 광고비율을 유지한 원 단위 이분 탐색이며 현재 물류 요금대가
유지된다는 조건이다. 판매가 변경으로 요금대가 바뀌면 실제 요금으로 재계산한다.

## 확정되지 않은 입력

[공식 요금](https://marketplace.coupang.com/rocket-growth)의 2026-10-23
관측은 입출고/배송 시작 가격이다. 상품의 사이즈·카테고리·최종 판매가와
계정 프로모션은 WING에서 확인해야 한다. 최저표를 자동 확정 원가로 쓰지 않고
낙관/기준/보수에 각각 1/1.25/1.6배를 적용한 민감도다.
수수료10.8/12%, 관세0/8/13%, 매입원가 가산0%(1688 표시가 기준), 체류일·보관·반품·고정비는
모두 가정이다. HS 품목별 관세나 카테고리별 확정 수수료로 표시하면 안 된다.
보관·반품 무료 프로모션은 계정 확인 없이 자동 적용하지 않는다.

사입100개는 계산 예시다. 판매자 월 판매예측은 기본 null이다.
`pair_overrides`에 상품별 `monthly_seller_units`와 `settlement_delay_days`를
명시해야 재고 소진일·정산지연 포함 현금 원금 회수일을 계산한다.
재고 원금 회수는 미리 지급한 재고비를 판매당 현금 유입에 다시 더해
원가를 이중 차감하지 않도록 계산한다. 첫 배치에서 원금 회수가 불가능하면 null이다.
회수일은 VAT 정산을 같은 기간에 배분한 모형이며 실제 환급·정산시점과 다를 수 있다.
카탈로그 월 리뷰×15는 참고 열로 보존하고 판매자 예측으로 자동 전환하지 않는다.

일반과세 기준: [국세청](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7695&mi=2272).
수입 VAT 관계: [관세청](https://www.customs.go.kr/kcs/ad/tax/BuyTaxCalculation.do).
개인직구 면세, 간이과세, 법인세·소득세, 계정별 프로모션, 실정산 대사는 별도다.

## 실제 비용으로 재실행

예제 설정을 새 JSON으로 복사하고 국내 할인/쿠폰, 수수료, 중국·국제 운송,
HS 관세율, WING 물류 요금, 체류일, 반품 조건, 광고비, 판매자 수요를 입력한다.
`pair_overrides`는 해당 `pair_id`에 공통 가정 덮어쓰기를 적용한다.
크기별 `size_starting_fees_ex_vat` 값을 실제 견적으로 대체하면
`logistics_multiplier=1`로 설정하여 시작표 배율을 중복 적용하지 않는다.
출력은 새 폴더로 분리해 기존 조사와 비용 가정을 보존한다.

```bash
python -m pytest -q tests/test_rocket_margin.py
```


## 1688 배대지 대량 합배송

국제운송은 개별 상품의 해외 직배송료가 아니라 `shipment.totals`의 배치
총액으로 입력한다. 중국 내륙배송·사입대행·보험·통관·검수·센터입고 운송도
배치 총액을 배분한다. 포장·라벨·세트 작업비는 판매단위별 입력을 유지한다.
같은 비용의 배치 총액과 기존 개당 금액을 동시에 넣으면 오류로 중복 계상을 막는다.
`bulky` 분류만으로 운임을 두 배 적용하던 계산은 제거했다.

현재 예제는 각 비교 조합별로 판매단위 100개를 사입하는 **별도 가상 배치**다.
193개 대안 상품을 하나의 실주문에 함께 실었다는 뜻이 아니다. 기존 운송 가정액의
100배를 배치 총액으로 옮겨 비교 기준을 보존했으며, 실제 배대지 견적은 미확보다.
따라서 이 변경만으로 실제 대량 운임이 저렴해졌다고 확정하지 않는다.
예를 들어 운임 10만원이 확정된 동일 배치에서 판매단위 500개라면 단위당
200원이다. 수량·중량·부피가 바뀌면 배대지 총견적도 다시 입력해야 한다.

동일 상품 배치는 `batch_units`가 국내 판매단위 수량이다. `quantity_ratio_assumed`
가 2이면 판매단위 100개는 공급자 실물 200개다. MOQ를 세트 구성 수로 해석하지 않는다.
혼합 배치는 `shipment.items`에 `id`(pair_id), `quantity`(공급자 실물 수량)를
모두 적고 `basis`를 `units`, `weight`, `volume`, `value` 중 선택한다.
중량·부피·금액 기준은 각 항목에 `unit_weight`, `unit_volume`, `unit_value`를
동일 단위로 명시해야 한다. 자동 추정하거나 누락값을 0으로 채우지 않는다.
모든 공통비는 선택한 기준을 사용하므로 비용마다 다른 기준이 필요한 견적은 별도 배치로
계산하거나 사전 배분해야 한다. SKU 수량에서 해당 판매단위 재고 수량을 산출한다.
금액은 소수 둘째 자리까지 최대 나머지 방식으로 배분해 총액을 보존한다.

HTML의 상품별 상세에 합배송 총수량·판매단위 수량·국제운임 총액과 단위당
배분액이 표시된다. 엑셀 `배대지 합배송 배분` 시트에는 모든 공통비의
배치 총액 → 해당 SKU 배분액 → 판매단위당 비용을 저장한다.

## 사업자 해운 운영 경로와 실입력 검증 (2026-10-23 개정)

운영 경로는 **1688 사입 → 중국 배대지 합포장 → 해운 → 한국 사업자통관 →
로켓그로스 입고**다. `configs/rocket-margin.example.json`의 `bulk_plan`은 실입력
양식이며 누락값은 null이다. `bulk_plan_overrides[pair_id]`로 상품별 입력을 덮어쓴다.
기존 3개 가정·6개 크기 결과는 과거 가정의 민감도 비교이며 실운송 견적 계산이 아니다.
`사업자사입 검증` 시트와 HTML의 준비 현황에서 실제 계산 가능 여부를 구분한다.
준비가 안 된 상품의 실제 마진은 null이며 가정 마진 양수만으로 추천하지 않는다.

`app.bulk_import.freight_quote`가 사용하는 공개 요금은 다음과 같다.

- 신성진 위해 LCL **월·수·금 선택 링크**: 88,000원/CBM, 0.1CBM 올림.
  DOC 22,000원/B/L, 물량 0.2CBM 또는 20kg 이상이면 핸들링 22,000원/B/L,
  선택 CO 발급 33,000원/B/L. 조건 경계와 중량 할증은 발주 전 확인한다.
  CFS 이후 국내 운송은 별도다. 기본운임만을 전체 운송비로 표시하지 않는다.
  `sDlvrWayCd=3`이 해당 노선이며 다른 선택값의 표를 혼합하지 않는다.
- 넥스트 위해-인천1 BASIC 소량 해운: 1kg 6,200원, 5kg 12,600원,
  10kg 20,600원, 최소1kg·0.5kg 올림. 이번 고정표는 10kg까지만 지원한다.
  기본 국내택배 포함. 업체가 부피무게를 적용한다고 확인한 경우에만 68kg/CBM을 적용한다.
  이 전자상 소량요금을 사업자 LCL에 자동 적용하지 않는다.
  `small_business_route_confirmed=true`로 사업자통관 수락을 확인해야 실제 계산에 쓴다.
  동일 배송지 구간을 `center_inbound`로 또 청구하면 오류이며 실제 별도 구간은
  `separate_onward_leg=true`로 구분한다. 쿠팡 입고 작업·운송은 기본택배 포함과 별개로 확인한다.

두 요금표의 공개 금액에서 부가세 포함 여부를 임의로 판단하지 않는다.
운송/통관/검수 견적은 실입력에서는 총 현금액으로 보고 부가세를 추가하지 않으며
공제도 임의 생성하지 않는다. 별도 수입 VAT와 확인한 WING 요금의 VAT는 기존
원장으로 구분한다. 합산 운송료에 국내 서비스가 포함될 수 있으므로 관세 과표를
운송 총액으로 자동 복원하지 않고 `customs_value_per_sale`을 신고·관세사 기준으로
별도 받는다. CO 비용을 냈다고 관세를 자동 0%로 바꾸지 않는다.

마스터박스별 `count`, `units_per_carton`(공급자 실물 수량), `length_cm`,
`width_cm`, `height_cm`, `gross_kg`를 `cartons` 배열로 입력한다.
실물 발주수량과 박스 수량 합계를 검증하고 상품별 MOQ를 비교한다.
반쪽 박스는 별도 박스 항목으로 실제 포장수량을 넣는다.
판매수량 또는 실물 수량이 소수면 실행하지 않는다. 대표 옵션가격은 유지하며
다량 할인·첫 주문 쿠폰·판매자 무료배송은 공급자 확인 없이 차감하지 않는다.
중국 내륙비·구매대행·환전/결제·국내 통관대행·도착지 추가비·국내입고운송·
검수·인증·팔레트/재작업비는 각각 배치 총액을 받는다. 없음/불필요를 확인한
항목만 명시적 0으로 입력한다. 인증비는 이번 배치에 전액 반영하며 미래 판매량에
임의로 나누지 않는다. 관세율·카테고리 수수료·WING 입출고/배송비·보관비·무료일,
바코드/한글 표시/입고 준비·수입 증빙도 확인 여부를 분리한다.
실입력 WING 요금에는 임의 1.25배 등의 배율을 적용하지 않는다.

반품·재고손실의 착지비 기준에는 포장·검수·사전 준비비까지 포함하도록 보완했다.
